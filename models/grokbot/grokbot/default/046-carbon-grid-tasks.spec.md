## 产品边界

实现：创建任务、分派与改派成员、推进状态（待办→进行中→评审→已完成）、筛选、活动记录、受限任务权限拒绝、申请权限、安全返回。不包含：任务详情、评论附件、截止日期、真实权限审批与通知。

## 状态地图

1. 任务列表（默认，筛选「全部」）
2. 筛选：分派给我 / 未完成
3. 创建校验错误：缺标题或负责人
4. 权限不足弹窗：对受限任务推进或改派
5. 已申请：弹窗关闭，活动记录黄色项 + 黄色通知
6. 已返回：弹窗关闭，绿色通知，焦点落到可操作任务
7. 已完成任务：推进按钮禁用

## 正常流程

1. 在新建任务行输入「首页首屏动效走查」，分派给「林小禾」，初始状态待办，点「创建任务 ＋」→ 新行置顶闪蓝，活动记录新增「许岚 创建任务…并分派给 林小禾（待办）」
2. 在该行负责人下拉选「周一舟」→ 活动记录「从 林小禾 改派给 周一舟」
3. 点「推进到 进行中 →」→ 状态标签变蓝色进行中，活动记录新增推进记录
4. 继续点推进到评审、已完成 → 标签依次变紫、绿，按钮变禁用「已完成」

## 异常触发与恢复

触发：在带 🔒 的「预算审批：外包动效费用」（财务组 · 受限）点「推进到 进行中 →」，或在「服务器迁移评估」（工程组 · 受限）的负责人下拉中改派。
反馈：弹出顶部红线弹窗「权限不足 · 这次变更没有保存」，写明尝试的操作、缺少的权限「财务组 · 编辑任务」与当前角色；任务状态与负责人保持原值（下拉被回滚），活动记录新增红色「尝试… — 已被拒绝，未写入」。
恢复：①点「申请访问权限 →」→ 活动记录新增黄色申请（含理由），右上黄色通知「申请已发出…任务暂时保持原样」；②或点「返回可操作的任务」（或 Esc）→ 绿色通知并聚焦首个可推进的设计组任务 → 点「品牌色板与图标重绘」的「推进到 评审 →」→ 状态变紫色评审并记活动，完成一次有权限的变更。

## 数据变化

- 初始：5 个任务、2 条活动。
- 创建后：6 个任务，新任务 id 6 置顶；活动 +1。
- 改派、推进：对应任务字段变化，每次活动 +1。
- 权限拒绝：受限任务的状态与负责人不变；活动 +1（红色拒绝）。
- 申请：任务不变；活动 +1（黄色申请）。
- 返回后有权限推进：品牌色板 进行中 → 评审；活动 +1。

1. 正常：输入「首页首屏动效走查」→ 选林小禾 → 创建 → 看到新行与创建记录
