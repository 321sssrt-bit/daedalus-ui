# 048-terminal-go 复现规范

## 规范元数据

- 规范版本：2
- 主视口：390 × 844 px
- 对应页面：`048-terminal-go.html`
- 复现范围：青灰航站楼风格的移动端订票原型，覆盖搜索路线、班次选择、座位选择、订单确认与登机凭证五个界面，含座位售罄异常与改选恢复，全部状态在同一 HTML 内可交互走通。

## 响应式规则

- 宽屏：`.phone` 宽 390 px、高 844 px 居中，外有 24 px 舞台内边距。
- 断点 430 px：`.phone` 宽 100vw、高 100vh（含 100dvh），圆角与外壳内边距归零，无边框阴影，贴合窗口。
- 内容区纵向滚动，顶栏与步骤条固定，不出现横向滚动。

## 动效与反馈

- 步骤切换即时：`.screen.active` 直接切换，无入场动画。
- 按钮按压 `transform: translateY(1px)`；进度条与按钮悬停 0.15s 背景过渡。
- Toast 底部浮现 0.25s，2.2s 后消失。
- `prefers-reduced-motion: reduce` 时关闭全部动画与过渡，仅保留即时反馈。

## 产品边界

- 只演示「北京/上海」单向订票流程，不实现真实支付、乘机人管理、退改签与多段联程。
- 售罄只发生在座位 07A 一处，用于演示实时余票校验；班次列表中的「仅剩 3 席」为静态提示，不参与售罄拦截。
- 数据仅存于页面内存，刷新即重置；无后端、无登录。

## 正常流程

1. 搜索路线：在搜索屏填出发「北京」、到达「上海」、日期，点「搜索班次」→ 状态进入班次列表，步骤条亮起第 2 步，顶栏显示「选择班次」。
2. 选择班次和座位：点 MU5137「选择」→ 进入座位图；点 07B → 座位高亮变青色、摘要显示「07B」。
3. 确认订单：点「确认订单」→ 进入确认屏，乘客、路线、班次、座位、金额全部回显。
4. 看到行程凭证：点「确认并出票」→ 进入凭证屏，出现绿色对勾与深青登机牌（含条码票根、座位 07B）。

## 异常触发与恢复

- 主动触发：在座位图选择带「需校验」角标的 07A，点「确认订单」再点「确认并出票」。
- 题定反馈：确认屏顶部出现红色售罄横幅「座位已售罄」，说明 07A 已售罄并保留路线条件；「确认并出票」变「无法出票」并禁用。
- 恢复操作：点横幅内「改选座位」（回座位图）或「改选班次」（回班次列表）。
- 重新成功：改选 07B → 确认订单 → 确认并出票，凭证座位号显示 07B。

## 数据变化

- 出票前：state.flight 与 state.seat 为空 → 选择后写入班次与座位；出票成功后凭证读取同一份 state 生成票号与登机口。
- 售罄触发时：不生成凭证、不写入票号，state 保持所选 07A 与路线不变；仅横幅展示，改选后 seat 重置为空再重新写入。
- 金额随所选班次实时重算（票价 + 90），改选班次后价格同步更新。

## 人工验收步骤

- 正常闭环：打开页面 → 点「搜索班次」→ 点 MU5137「选择」→ 点 07B → 点「确认订单」→ 点「确认并出票」，预期看到「出票成功」与深青登机牌、座位 07B。
- 异常恢复：从班次列表进入座位图 → 点 07A → 点「确认订单」→ 点「确认并出票」，预期出现红色售罄横幅且按钮变「无法出票」→ 点「改选座位」→ 点 07B → 确认并出票，预期凭证座位号更新为 07B。
