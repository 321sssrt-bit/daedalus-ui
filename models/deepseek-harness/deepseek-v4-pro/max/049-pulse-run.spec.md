## 响应式规则

- 宽屏：`.phone` 宽 390 px、高 844 px 居中，外有 24 px 舞台内边距。
- 断点 430 px：`.phone` 宽 100vw、高 100vh（含 100dvh），圆角与外壳内边距归零，无边框阴影，贴合窗口。
- 面板纵向滚动，底部导航固定，不出现横向滚动。

## 内容与数据

- 本周目标 25 km，初始已完成 18.6 km（74%）。
- 近 7 日平均心率初始序列：142 / 149 / 146 / 152 / 148 / 151 / 147，对应周一到周日；上周基准 146 bpm。
- 合理范围：距离 0.1–50 km、时长 1–600 分钟、平均心率 40–220 bpm。
- 最近记录初始两条：6月17日 晨跑 4.2 km 31 分钟 149 bpm；6月16日 夜跑 3.1 km 24 分钟 143 bpm。
- 校验规则：任一字段为空、非数字或超范围即整单不保存，并逐个字段标红。

## 动效与反馈

- 进度条宽度以 `transition: width 0.4s ease` 平滑变化。
- 按钮按压 `transform: translateY(1px)`；chip 与输入框焦点过渡即时。
- Toast 底部浮现 0.25s，2.3s 后消失。
- `prefers-reduced-motion: reduce` 时关闭全部动画与过渡，进度条直接跳变，仅保留即时反馈。

## 产品边界

- 只记录「跑步 / 骑行 / 快走」三种活动，不做 GPS 轨迹、地图、社交与运动计划。
- 数据仅存于页面内存，刷新即重置；无账号体系与云端同步。
- 趋势只展示近 7 日平均心率一条折线，跑量只影响目标进度，不做多维图表。

## 正常流程

1. 输入活动数据：在今日面板的类型 chip 选「跑步」，分别填距离 5.0、时长 32、平均心率 152。
2. 保存记录：点「保存记录」→ toast「已保存 · 本周进度 +5.0 km」，最近记录顶部新增一条「跑步 5.0 km · 今天」。
3. 看到目标进度变化：目标百分比由 74% 升为 94%，「还差 6.4 km」变为「还差 1.4 km」，已完成 18.6 → 23.6 km。
4. 查看更新后的趋势反馈：点「查看更新后的趋势 →」进入趋势面板，折线末点更新为 152 bpm，平均心率与趋势说明重算。

## 异常触发与恢复

- 主动触发：在距离输入框填 300（超出 0.1–50 km 范围），其余字段合理，点「保存记录」。
- 题定反馈：距离字段红框、底色 `#fdecec`、红字「请输入 0.1–50 km 之间的距离」，toast「保存失败：请修正标注的错误字段」；目标进度与趋势折线保持不变。
- 恢复操作：把距离改回合理值（如 5.0）。
- 重新成功：点「保存记录」→ 进度、最近记录与趋势全部重算，toast 成功。

## 数据变化

- 保存前：done = 18.6 km，trend 末点 147，最近记录 2 条。
- 保存有效数据（5.0 km / 152 bpm）后：done = 23.6 km，trend 序列右移为 149 / 146 / 152 / 148 / 151 / 147 / 152，最近记录增至 3 条，百分比 74% → 94%。
- 无效数据提交时：done、trend、记录条数均不变，不产生任何写入；仅字段错误态切换。
