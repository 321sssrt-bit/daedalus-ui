# 028 长表单

## 意图元数据

- 意图版本：1
- 对应规范：`028-shipform.spec.md`
- 说明：本文件不参与结构、尺寸、状态或交互验收。

## 设计意图

长表单的第一要义是「分得清、找得到、存得住」。这里把进港申报做成「船舶资料簿」：船体蓝顶栏 + 三节结构（船体/船员货物/检疫），顶部步骤条区分已完成/当前/待填，每节头部用数字徽章与必填计数；「跳至第 N 节」提供长页面快速定位；保存草稿与提交明确分离——草稿提示「保存到本机」，提交时逐字段校验并聚焦首个错误，绝不静默失败；一屏内的必填星号与 err 文案让用户知道差在哪。

## 适用场景与目标用户

适合政务申报、企业登记、体检问卷等必须一次填完的长表单；目标用户是办手续的当事人或代办——他们常被长表单劝退，因此结构上必须「三节+可跳转」，校验上必须「指出字段」而非只说「表单有错」。

## 非目标

- 不做分页向导（单页三节）、不做暂存列表
- 不做自动保存时间戳（草稿为提示条）
- 不采用 SaaS 蓝紫或绿野风；船体蓝+海雾白+金锚的航务气质

## 复刻提示词

「进港申报 · 船舶资料」长表单：海雾白页面、顶部船体蓝栏「⚓ 进港申报 · 船舶资料 / 单号 PR-2026-0904-07 · 受理窗口 3 号」；下方步骤条三节（第一节 ✓已完成、第二节 当前高亮、第三节 待填）；三节字段区依次为船名/MMSI/船型/总吨位（必填星标）、船员 21 人/货物类型、压载水/上一港口；字段焦点为海蓝描边、错误为橙底橙边并显示 err；「跳至第一节/二/三」胶囊、底部「保存草稿」与海蓝「提交申报」；提交失败聚焦首个错误，成功显示「已提交 ✓」；像港务局窗口的申报单，分节清楚、校验透明。
