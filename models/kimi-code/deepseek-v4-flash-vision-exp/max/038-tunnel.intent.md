# 038 故障

## 设计意图

故障页的第一职责是「让人不慌」。这里把故障做成廊桥地铁 2 号线「途中故障」：地铁橙+轨道黑的运营因子，状态条先说清楚「哪条线、哪段、什么原因（信号丢失）」；「这趟车慢下来了」指出这不是罢工而是核对路况；工单编号 #2LINE-0714 让延误成为可追踪事实；重试按钮是唯一主行动，且恢复后给出「信号已恢复 + 可凭编号申请改签」的回执——人话结尾落在「你怎么办」，而不是停在「出错了」。

## 适用场景与目标用户

适合出行、物流、支付等「中断必须安抚+可追踪」的场景；目标用户是正在通勤的乘客——他们只需要三件事：发生了什么、多久恢复、出了事找谁（编号），因此页面按「状态→原因→编号→行动」顺序组织，无冗余。

## 非目标

- 不做自动刷新倒计时（重试为手动）、不做换乘方案
- 不做报错代码细节堆砌（信号丢失一句即可）
- 不采用红色报警风；地铁橙为唯一强调色，灰白为常态

## 复刻提示词

「廊桥地铁」的故障页：灰白屏、顶部「‹ 行程 / 廊桥地铁」；橙色警示条「当前线路：2 号线 · 途中故障 / 廊桥站—白站段区间信号丢失，列车限速通过」；中央矢量插画——停在地下的橙色列车、信号中断气泡与「B1 · 信号中断」标注；大标题「这趟车慢下来了」，正文「不是地铁在罢工，是前方信号系统正在核对路况。预计 8–12 分钟恢复正常」；白色工单卡「故障受理编号 # 2LINE-0714 · 记录时间 14:07 · 人工处理中」；底部地铁橙实底「重新查询线路状态」（点击 900ms 后「已恢复 ✓」+ 绿色回执「可凭编号申请免费改签」）与细边「回到首页」；像站台广播一样直接，但先安抚后解决。
