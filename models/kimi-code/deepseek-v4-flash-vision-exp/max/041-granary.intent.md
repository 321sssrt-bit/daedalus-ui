# 041 购物零售产品

## 意图元数据

- 意图版本：1
- 对应规范：`041-granary.spec.md`
- 说明：本文件不参与结构、尺寸、状态或交互验收。

## 设计意图

41 题把「山货铺」做成一座口袋里的老山货店：奶油纸底、墨绿主按钮、深青山蓝点缀，商品列表用 emoji 插画而非照片，保持「逛山货摊」的亲民感；整个流程控制在「列表→详情→车→提交→回执」五视图，缺货异常做成「第一次提交才暴露」的真实库存场景——用户会先看到缺货提示与金额归零，再被引导改规格，而不是一开始就被阻止，这更贴近线下买菜的经历。

## 适用场景与目标用户

适合地方特产、生鲜、社区团购等小体量购物；目标用户是街坊型买家，对价格与运费的诚实度要求高于推荐算法；购物车满 39 包邮线明示，缺货明确指品并给改选路径。

## 非目标

- 不做登录/支付方式/多店铺分账
- 不做收藏夹、搜索、排序
- 不做复杂库存回滚演示；只演示「一件商品某规格缺货」

## 复刻提示词

口袋里的「山货铺」：奶油纸色手机屏，顶部「山货铺」与叶绿「布口袋」计数；商品两列卡（🌰野生山栗 500g ¥12.8 / 🍯土蜂蜜 350g ¥58 / 🫒柴火油茶籽 1kg ¥39.8），进详情可选规格（大颗粒/中颗粒-易缺货/碎粒）与数量加减、墨绿「加入布口袋」；购物车动态合计与橙红「临时缺货」横幅，缺货行金额归零并附「改为大颗粒」；提交页摘要+收货信息，提交后绿色圆形回执「订单已提交 #OR-2026-0904-127 / 实付金额 / 预计送达」；像老铺记账票据一样清楚，缺货也有下文。
