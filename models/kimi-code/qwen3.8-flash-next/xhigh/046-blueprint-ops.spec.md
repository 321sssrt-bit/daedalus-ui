## 产品边界

本原型只做"桥面改造工程出图协同"这一件事：任务看板 + 成员分派 + 阶段推进 + 活动流 + 一层权限模型（外来客人默认只能动公开卡，T-03 属结构组专有需申请）。不做真实账号体系、多人实时同步与后端持久化；权限"审批"由页面上的演示按钮代表审批人操作，边界在"拒绝必须不写入、恢复必须走申请或退出"。

## 状态地图

| 状态 | 触发 | 可见特征 |
|---|---|---|
| 常态（只读受限区） | 页面加载 | 角色章"外来审图员（只读受限区）"，T-03 斜纹锁定，横幅隐藏 |
| 拒绝态 | 点击 T-03 推进/改分派 | 红横幅"权限不足：缺少「受限图签区编辑」权限"，正文声明未写入；卡闪红；toast err；日志 sec 条目 |
| 待审批态 | 点"申请访问" | 横幅改"访问申请已发出 · 等待结构组审批"，批准钮出现，申请钮 disabled |
| 已授权态 | 点"演示：审批人点击批准" | 横幅 granted-mode 绿色并引导推进 T-03，角色章转绿，T-03 解锁，日志审批条目，toast ok2 |
| 恢复完成态 | 已授权后点 T-03"推进" | T-03 章变 IN REVIEW 红色，日志普通条目，横幅可收起 |
| 新建态 | 点"＋新建图签任务" | 表单展开；空标题→红字错误；成功→新 st0 卡 + 日志 + toast |
| 归档终态 | 任务推到 st3 | 章 ARCHIVED 绿色，推进钮 disabled"已归档" |

## 正常流程

1. 点"＋新建图签任务"，填标题/分派/优先级，提交 → 新卡以 DRAFT 出现，日志与计数更新。
2. 卡上 select 改分派 → 日志记录"分派给×"。
3. 点"推进"逐档：DRAFT → IN PROGRESS → IN REVIEW → ARCHIVED。
4. 右栏活动流按时间倒序累积所有操作。
5. 全程公开卡操作不受权限阻碍。

## 异常触发与恢复

- 触发：对 T-03（受限图签）点"推进"或改分派——页面明示"操作将触发权限校验"。
- 失败表现：红横幅写明缺少「受限图签区编辑」权限且"本次变更未写入，任务状态与分派保持原样"；改分派回滚原值；卡闪红、toast err、日志 sec 条目。
- 恢复：点"申请访问"→"演示：审批人点击批准"获得权限（或点"安全返回可见任务"退出受限语境）→ 对已解锁的 T-03 完成一次真实推进，异常闭环结束。

## 数据变化

- 拒绝：零写入——任务数组、分派、阶段、日志（除安全记录条目）均不变。
- 申请/批准：仅权限位 perms.restrictedEdit 与角色文案变化，任务数据不动。
- 批准后推进：T-03 stage 1→2，新增普通日志条目。
- 新建：任务数组 +1（id 递增、st0），计数 `#taskCount` +1。
- 安全返回：仅关横幅与提示，无任何数据变化。

## 人工验收步骤

正常闭环：① 新建"南引桥伸缩缝大样图"分派林一苇 → 出现 DRAFT 卡；② 连点推进三次至 ARCHIVED，章与钮状态同步；③ 右栏日志逐条对应每次操作。

异常恢复：① 点 T-03"推进" → 拒绝四件套出现且 T-03 仍 IN PROGRESS；② 点"申请访问"再点"演示：审批人点击批准" → 全页转授权态、T-03 解锁；③ 再点 T-03"推进" → 成功变 IN REVIEW，证明恢复后完成了有权限的变更。
