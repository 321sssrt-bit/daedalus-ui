## 规范元数据

- 规范版本：2
- 主视口：390 × 844 px
- 对应页面：`042-mint-terminal.html`
- 复现范围：移动端「薄荷随身转账终端」单文件原型——行情首页选资金来源与收款人 → 键盘输入金额 → 指令核对页确认 → 执行进度 → 转账凭证；确认时对超可用余额的金额弹出「余额不足」拦截面板并阻止提交，可降金额（AMEND）或就地切换资金来源后重新确认成功；五个视图共用同一套墨绿黑终端设计系统。

## 产品边界

实现随身金融终端内的一笔转账闭环：可用余额与资金来源展示与切换、已验证收款人名录、金额键盘输入与快捷芯片、指令核对（含手续费与预计结余）、执行进度与转账凭证，以及余额不足的拦截与两种恢复（降金额、换资金来源）。不含：新增/编辑收款人、扫码与通讯录、理财与信贷、多币种换汇、真实后端与推送、凭证分享与回单下载、生物识别；「返回行情」与「再来一笔」是唯一出口。

## 正常流程

1. 首页默认「活期余额 ¥8,642.30」；点「陈某某」行 → 该行提亮并按下变色，进入金额屏，上下文回显「陈某某 ****4410」，页脚 IDLE。
2. 点芯片「500.00」或键盘输入 → 大数字实时格式化、合计行变「含手续费合计 500.50」、VERIFY 由禁用转薄荷可用。
3. 点 VERIFY → 指令核对页：薄荷 16 px 转账金额、扣减合计、预计结余 8,141.80、页脚 ARMED 闪烁。
4. 点 EXECUTE → 执行页三步依次琥珀▸→薄荷■，进度条 1.9 s 推满，自动到凭证页：印章落下、凭证十行（含随机编号）、页脚 SETTLED。
5. 点「返回行情」→ 余额 8,141.80、30日出账 +500.50、近期出账新增「陈某某 随身转账 -500.00」共 4 笔。

## 异常触发与恢复

- 主动触发：金额屏点警示色芯片「超限 12,000.00」（或键盘输入任意超可用额金额）→ VERIFY → 确认页（此时预计结余已呈负值警示色）→ 点 EXECUTE。
- 反馈：不进入执行，停留确认页；拦截板抖动出现，逐字显示可用余额 ¥8,642.30、需扣减 ¥12,000.50、缺口 ¥3,358.20 与「转账已拦截，款项未提交」；页脚转 BLOCKED；余额、出账、统计一律不变。
- 恢复 A（降金额）：点拦截板「调整金额 AMEND」→ 回金额屏且 12,000 原值保留 → 改小（如芯片 500.00）→ VERIFY 回确认页时拦截板自动清除 → EXECUTE 成功出凭证。
- 恢复 B（换来源）：在确认页来源栅格点「保证金账户」（可用 24,500 ≥ 12,000.50）→ 拦截板即时隐藏、预计结余转正、页脚回 ARMED → 再点 EXECUTE 成功出凭证；原来源分文未动。

## 数据变化

- 转账成功：所选来源余额 -= 金额 + 0.50；30日出账 += 金额 + 0.50；近期出账头部插入一笔（姓名/随身转账/来源名/金额/当前时间），计数 +1；凭证为一次性新随机编号。
- 切换来源（含拦截中切换）：仅改选中标记与预计结余重算，不动任何余额。
- 被拦截时：任何余额、统计、出账记录均不得变化，金额与收款人输入必须保留；AMEND 后金额输入不得被清空。
- 「再来一笔」：收款人与来源保留、金额清零；「返回行情」后首页三处数字必须与凭证页一致。

## 人工验收步骤

正常闭环：① 打开页面 → 首页见 8,642.30 与三资金格；② 点「林某某」→ 金额屏；③ 点芯片 500.00 → 合计 500.50、VERIFY 亮起；④ VERIFY → 指令单结余 8,141.80 为灰字；⑤ EXECUTE → 三步点亮后自动凭证，印章 + 4820 编号；⑥ 返回行情 → 余额 8,141.80、出账 4 笔。
异常与恢复 A：① 金额屏点「超限 12,000.00」→ 屏现超限警示；② VERIFY→EXECUTE → 拦截板现缺口 3,358.20、页脚 BLOCKED、余额未动；③ 点 AMEND → 回金额屏仍显示 12,000；④ 点 500.00 → VERIFY → EXECUTE → 凭证成功。
异常与恢复 B：① 同法触发拦截；② 不点 AMEND，直接在来源栅格点「保证金账户」→ 拦截板消失、结余转正；③ EXECUTE → 凭证「资金来源 保证金账户」；④ 返回行情 → 保证金余额 12,499.50、活期仍 8,642.30。
减弱动态：开启系统减少动态后重复异常触发，拦截板无抖动直接出现，执行页三步直接全绿、进度条满格。
