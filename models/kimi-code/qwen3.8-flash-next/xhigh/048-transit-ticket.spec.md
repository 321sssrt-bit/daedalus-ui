## 产品边界

- 单趟购票闭环：搜索→班次→选座→确认→出票；不做支付、登录、改签、退票、多程。
- 票池为写死的 4 班次静态表，"实时核验"仅在确认动作时对触发席生效一次。
- 乘车人、车厢（05）、席别（二等座）固定，不做选择。

## 正常流程

1. 搜索页确认/修改两站与日期（可用交换钮或热门 chip）→ 点"搜索班次"。
2. 班次列表点一个未售罄班次（如 G102）→ 进入选座。
3. 点一个空闲座位 → "去确认订单"解禁 → 进确认单核对 7 行信息。
4. 点"确认出票" → 生成凭证：票头、撕线、席位、实付、`OR-` 票号、二维码 → 流程闭环。

## 异常触发与恢复

- 触发：选 G208（红色"紧俏"徽章）→ 其唯一空席 5F 带橙色"末席"角标明示风险 → 选中后确认 → 出票瞬间判定售罄。
- 失败表现：该席位置 sold，弹出红框告警明确点名车次/车厢/座位；金色虚线块保留「路线 · 日期 · 二等座」条件并声明无需重新搜索；未清除任何已填信息。
- 恢复：弹层内点"返回结果，改选可用班次" → 班次列表中 G208 已灰化（红条、余0张、"已售罄"红底徽章、双框斜章），其余班次照常可选 → 改选 G102 任一空座 → 确认 → 成功出票，重新走通闭环。

## 数据变化

- `state` 记录 from/to/date/train/seat，跨界面保留；`go()` 只切视图不清数据。
- 售罄触发时：`TRAINS` 中 G208 `sold=true、left=0`，重渲染后持久灰化（同一次会话内不可逆）。
- 出票时生成随机票号并以其为种子画二维码；"再买一张"仅重置 train/seat，路线条件不动。

## 人工验收步骤

正常闭环：
1. 打开页面 → 默认"上海虹桥→北京南"，点"搜索班次"→ 见 4 班次（G208 带红色紧俏徽章、余1张）。
2. 点 G102 → 选 5F（此班 5F 空闲）→ 去确认 → 确认出票 → 出现绿章车票与二维码，票号 `OR-20260315-6位` 格式。
3. 点"返回首页，再买一张"→ 条件仍在，交换钮互换两站后仍可再搜。

1. 搜索 → 点 G208 → 座位图上仅 5F 可点且带"末席"角标 → 选 5F → 确认出票。
