## 产品边界

本原型实现单人、单张二等座的路线查询、班次与座位选择、订单核对、主动售罄检查、两条改选恢复、行程凭证、同路线再订和新查询。数据在本次页面会话内连续保留，成功订单会改变对应班次余票和座位占用。

不包含真实铁路接口、实时票源、登录、证件核验、支付、退改签、多人订单、跨日期余票日历、真实二维码验票、刷新后的持久化或外部分享。验票图形和出票结果均明确标为演示。

## 状态地图

1. `search`：路线表单为初始页；可交换起讫站、修正空值或同站错误。提交有效路线进入 `results`；已有凭证时显示票夹保留说明。
2. `results`：保留路线与日期的班次时刻表；点击有票班次进入 `seats`，点击“修改路线”返回 `search`。从失败返回时原班次仍标为当前选择。
3. `seats`：显示当前班次、路线、日期、余票和 07 车座位图；点击座位更新已选状态和合计。“返回班次结果”回 `results`，“核对订单”在有选择时进入 `confirm`。
4. `confirm`：显示完整订单、价格、余票、下一序号；普通选择下“确认并出票”进入 `ticket`。演练或实际不可用选择在同一页展开售罄错误状态，仍是 `confirm`，不生成新页面或凭证。
5. `ticket`：成功凭证页；可“同路线再订一张”回到保留原路线的 `results`，或“开始新查询”回 `search`。两种操作均保留已生成订单和下一序号。
6. 所有状态共用固定品牌头部、5 步进度、色彩与组件令牌；隐藏页使用 `hidden`，不是外部页面或浮层。

## 正常流程

1. 保留默认值或输入有效出发地、目的地、日期，点击“查询青驿班次”；系统保存 `state.query`，清空上一笔未完成选择，显示 4 个班次并播报路线条件。
2. 点击任一正常有票班次；保存班次，若换了班次则清空旧座位，进入对应该班的座位图。
3. 点击普通可用座位；该座显示已选，底部摘要变为班次、座位、林舟和准确单价，“核对订单”启用。此时尚未扣余票。
4. 点击“核对订单”；确认页显示同一路线、日期、班次、起讫时间、07 车座位、乘客、票价、0 元服务费、总额和下一序号。
5. 点击“确认并出票”；仅在座位可用且班次非演练时，余票减 1、座位转不可选、序号加 1，生成订单快照并进入凭证页。
6. 核对凭证编号、路线、日期、班次、起讫时间、座位、乘客、总额与 SVG。选择同路线再订或新查询可重复流程，序号从已有最大值继续。

## 异常触发与恢复

### 单座售罄后改座位

1. 查询后点击带“含售罄演练座位”的 G7609，再点击红色虚线 04C；底部仍正确显示 `¥128.00`。
2. 点击“核对订单”，可见即将检查 G7609 次 04C 的演练提示；点击“确认并出票”主动触发。
3. 页面明确报“G7609 次 04C 座已售罄”，不进入凭证页。G7609 余票仍为 3，票夹与下一序号不变，南京南—杭州东、日期、班次结果及 04C 选择仍可核对。
4. 点击“返回座位改选”，04C 保持已选供核对；改点普通可用的 04D，再核对并确认，即可成功生成 `¥128.00` 的凭证。

## 数据变化

- 查询：仅更新路线条件与未完成选择，不改余票、订单数组或序号。
- 选班：记录 `selectedTrainId`；换成另一班时清除旧 `selectedSeatId`，返回同一班时保留座位。选座只更新选择和显示合计，不提交库存。
- 成功：目标班 `remaining -= 1`，目标座位状态改为 `occupied`，`orderSeq += 1`，向 `orders` 追加快照并更新 `lastOrder`、票夹和凭证。首单示例为 `QY20260918-001`，下一单为 `QY20260918-002`。
- 失败：`remaining`、座位占用、`orderSeq`、`orders`、`lastOrder`、票夹数量全部不变；只记录并显示 `lastError`。预展示的下一路线凭证序号不被占用。
- 恢复：不清空 `state.query`；改座只替换座位，改班保留结果列表并在换班时清除不适用的旧座位。最终仅成功订单发生一次数据提交。
- 再订与新查询：清除未完成选择但保留历史订单、下一序号及已变化库存；浏览器刷新不属于持久化边界。
