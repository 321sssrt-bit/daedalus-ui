- 初始零钱为 `268000` 分，即 **¥2,680.00**；青澜演示卡为 `800000` 分，即 **¥8,000.00**；首页总可用为 **¥10,680.00**。三处及确认页、凭证中的余额必须由同一状态计算，不能写死扣款后的结果。
- 四位收款人及顺序：林澜（手机尾号 0826）、周远（手机尾号 1932）、陈予（手机尾号 6715）、苏禾（手机尾号 3489）。点击任一卡即选定并进入金额页；点击“更换”或返回键回到列表，当前卡显示勾与青色边框。
- 默认来源为零钱；青澜演示卡尾号 2026。来源卡字段顺序为名称、说明、可用余额、单选状态；金额页下方同步显示“将从〔来源〕扣款，当前可用〔余额〕”。
- 金额以文本接收，用正则与整数分转换校验；合法格式为非负整数加可选的 1–2 位小数，且转换后必须大于 0 分并属于安全整数。`0`、`0.00`、负数、非数字、逗号、科学计数法和三位及以上小数均不得进入确认页。合法示例 `88.80`、`120.5`、`3000` 分别换算为 `8880`、`12050`、`300000` 分。
- 金额格式统一为 `¥` 加千分位整数和两位小数；时间格式为 `YYYY年MM月DD日 HH:mm:ss`，使用本机当前时间；交易编号格式为 `RWyyyymmdd-四位序号`，本次页面会话首笔成功为 `0001`，第二笔成功为 `0002`。
- 确认页字段顺序：收款人、资金来源、当前可用、转账金额、服务费；服务费固定 **¥0.00**。超额提示必须包含“余额不足，未扣款”、当前来源可用余额、本次金额与差额。
- 成功凭证字段顺序：交易编号、转账时间、收款人、资金来源、转账金额、转账后来源余额。余额标签须明确为“转账后零钱余额”或“转账后演示卡余额”。
- 数据仅保留在当前页面会话；刷新会恢复初始演示资金。“再转一笔”只清空本笔收款人、金额、来源选择与凭证，不回滚余额和成功交易序号。
- 页面有 `role="status" aria-live="polite"` 的读屏状态区；余额不足面板另用 `role="alert"`；不得依赖控制台或浏览器提示框反馈。

## 产品边界

本原型只覆盖单币种演示转账：查看余额、选择一位常用收款人、编辑金额、选择零钱或青澜演示卡、核对并确认、处理余额不足、查看本次成功凭证及继续下一笔。所有状态在当前单文件页面会话内有效。

不包含真实资金划转、登录/实名、支付密码、收款人新增或删除、银行卡管理、手续费计算、转账限额策略、历史流水持久化、撤销/退款、收款请求、扫码和多币种。刷新页面即恢复初始演示数据；没有浮层、外部页面或网络请求。

## 正常流程

1. 初始首页显示总可用 **¥10,680.00**、零钱 **¥2,680.00**、青澜演示卡 **¥8,000.00**；点击“林澜”卡。
2. 金额页显示“转给 林澜 / 手机尾号 0826”，默认来源零钱；输入 **88.80**，也可通过“更换”返回改选收款人。
3. 保持零钱选中，点击“核对转账”；确认页显示林澜、零钱、当前可用 **¥2,680.00**、转账金额 **¥88.80**、服务费 **¥0.00**。
4. 点击“确认转账 ¥88.80”；系统以分执行 `268000 - 8880 = 259120`，成功序号从 0 变为 1，进入成功页。
5. 成功页显示“转账成功”、交易编号（尾号 `0001`）、当前时间、林澜、零钱、**¥88.80** 和“转账后零钱余额 **¥2,591.20**”。
6. 点击“再转一笔”回首页；总余额为 **¥10,591.20**，零钱为 **¥2,591.20**，演示卡仍为 **¥8,000.00**。收款人、金额清空，来源恢复零钱，可开始下一笔。

## 异常触发与恢复

### 主动触发

初始状态选择林澜，保持零钱，输入 **3000.00** 并点击“核对转账”；核对页允许展示该金额。点击“确认转账 ¥3,000.00”后，因 `300000 > 268000` 分而拦截：显示“余额不足，未扣款”，当前可用 **¥2,680.00**、本次需转 **¥3,000.00**、差额 **¥320.00**。不进入成功页。

失败时收款人林澜、金额文本 `3000.00`、来源零钱均保留；零钱、演示卡、总余额、成功交易序号均不变化；不生成新交易编号、转账时间或成功凭证。

### 降低金额恢复

在错误面板点击“降低金额”，返回金额页并全选 `3000.00`；输入 **120.50**，保持零钱，点击“核对转账”，再点击“确认转账 ¥120.50”。成功后零钱为 **¥2,559.50**，凭证金额为 **¥120.50**；若这是本会话首笔成功，交易编号尾号仍为 `0001`。

### 切换来源恢复

在同样的 **¥3,000.00** 超额错误面板点击“切换资金来源”，返回金额页且金额保留；点击“青澜演示卡”，其可用余额显示 **¥8,000.00**。点击“核对转账”，确认来源已变为青澜演示卡，再点击“确认转账 ¥3,000.00”。成功后演示卡余额为 **¥5,000.00**，零钱仍为 **¥2,680.00**；若这是本会话首笔成功，交易编号尾号为 `0001`。

扣款只在确认时且 `amountCents <= balances[sourceId]` 后执行一次整数减法；金额格式校验不在首页预扣，核对动作不扣款。余额不足时不得修改任一来源余额或总余额，不得增加 `transactionSequence`，不得生成交易编号、时间、成功记录或显示成功页，也不得清空收款人、金额和来源。重复点击失败确认仍遵守这些不变量。

## 人工验收步骤

以下 A、B、C 三组可分别通过刷新恢复初始值，避免不同示例互相影响；组内不得刷新。

### A. 正常闭环与累计扣减

1. 打开页面，确认总余额 **¥10,680.00**，点击“林澜”。
2. 输入 **88.80**，保持“零钱”，点击“核对转账”。
3. 核对林澜、零钱、当前可用 **¥2,680.00**、金额 **¥88.80**，点击“确认转账 ¥88.80”。
4. 确认成功凭证包含交易编号尾号 `0001`、当前时间、林澜、零钱、**¥88.80**、转账后零钱余额 **¥2,591.20**。
5. 点击“再转一笔”，确认首页总余额 **¥10,591.20**、零钱 **¥2,591.20**。
6. 点击“周远”，输入 **11.20**，点击“核对转账”，再点击“确认转账 ¥11.20”。
7. 确认第二张凭证编号尾号 `0002`、转账后零钱余额 **¥2,580.00**。
8. 点击“再转一笔”，确认总余额 **¥10,580.00**、零钱 **¥2,580.00**、演示卡仍为 **¥8,000.00**。

### B. 余额不足后降低金额恢复

1. 刷新后点击“林澜”，输入 **3000.00**，保持零钱，点击“核对转账”。
2. 点击“确认转账 ¥3,000.00”，确认出现“余额不足，未扣款”，可用 **¥2,680.00**、本次 **¥3,000.00**、差额 **¥320.00**。
3. 确认没有成功页；返回首页以外的当前状态仍保留林澜、`3000.00` 和零钱。不得观察到任何余额变化。
4. 点击“降低金额”，确认金额仍为 `3000.00` 且已被全选；输入 **120.50**。
5. 点击“核对转账”，确认页仍为林澜和零钱，金额为 **¥120.50**。
6. 点击“确认转账 ¥120.50”，确认成功凭证金额为 **¥120.50**、转账后零钱余额 **¥2,559.50**、交易编号尾号 `0001`。
7. 点击“再转一笔”，确认总余额 **¥10,559.50**，证明失败未扣款且恢复成功只扣了 **¥120.50**。

### C. 余额不足后切换来源恢复

1. 刷新后点击“周远”，输入 **3000.00**，保持零钱，点击“核对转账”。
2. 点击“确认转账 ¥3,000.00”，确认可用零钱 **¥2,680.00**、差额 **¥320.00**，且无成功凭证、无扣款。
3. 点击“切换资金来源”，确认金额仍为 `3000.00`；点击“青澜演示卡”，确认其选中态及可用余额 **¥8,000.00**。
4. 点击“核对转账”，确认收款人仍为周远、来源已改为青澜演示卡、金额仍为 **¥3,000.00**。
5. 点击“确认转账 ¥3,000.00”，确认成功凭证编号尾号 `0001`、金额 **¥3,000.00**、转账后演示卡余额 **¥5,000.00**。
6. 点击“再转一笔”，确认总余额 **¥7,680.00**、零钱 **¥2,680.00**、演示卡 **¥5,000.00**；再次进入任意收款人的金额页，两种来源显示同样余额。

### D. 输入边界与可访问反馈

1. 进入任一收款人的金额页，依次输入 `0`、`-1`、`abc`、`1.234` 并点击“核对转账”；每次均应停留原页、出现内联错误且不显示确认页。
2. 清空金额，确认“核对转账”禁用；输入 `0.01` 后应可进入确认页。
3. 仅用 Tab 与 Enter 选择收款人、来源和按钮，焦点始终可见；超额错误出现时读屏状态应能表达“余额不足，未扣款”。
