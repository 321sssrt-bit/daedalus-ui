## 产品边界

- 单一路线查询与购票闭环：不含注册登录、支付收银台、改签退票流程与多乘客管理。
- 班次与铺位为内置演示数据；售罄判定只认两处 ◆ 标记（K117 班次、12 号下铺铺位）。
- 行程凭证为页面内出票结果，不含真实二维码验票与钱包加卡。
- 异常仅覆盖「班次或座位售罄」一类；运力、天气等其他异常不在边界内。

## 正常流程

1. 搜索页确认或修改出发、到达、日期（默认北京西 → 成都 · 11月12日），点「查询车次」。
2. 班次列表点选无 ◆ 标记的班次（如 K817）。
3. 铺位页点一枚可选铺位（如 3 号中铺），点「确认铺位」。
4. 订单确认页核对车票式摘要，点「提交订单」。
5. 复核通过，进入行程凭证：红头车次条、蓝色票面信息、条形码与打孔票根齐备。

## 异常触发与恢复

- 触发入口（页面明示）：搜索页与列表页提示「K117 与 12 号下铺 带 ◆ 复核标记，选中并提交会触发售罄检查」；K117 班次卡与 12 号下铺按钮常驻 ◆ 标记。
- 触发 A（班次售罄）：选 K117 + 任意可选铺位 → 提交订单 → 售罄视图指出「K117 次硬卧 刚刚售出最后一张」。
- 触发 B（铺位售罄）：选其他班次 + ◆ 12 号下铺 → 提交订单 → 售罄视图指出「×× 次 · 07 车 12 号下铺」。
- 拦截语义：「车站复核未通过，订单未扣款」；路线条件条保留「北京西 → 成都 · 11月12日 周四」。
- 恢复路径 A：「返回班次列表改选」→ 班次列表（搜索条件原样回填）→ 选 K817 → 选可选铺位 → 提交 → 出票成功。
- 恢复路径 B：「仅换铺位」（班次未售罄时）→ 铺位页重选可选铺位 → 提交 → 出票成功。

## 人工验收步骤

正常闭环：
1. 打开 `048-ticket48.html`，确认手机框内搜索页默认「北京西 → 成都 · 11月12日」。
2. 点「查询车次」→ 班次列表出现四趟车，点 K817（无 ◆ 标记）。
3. 铺位页点「3号中铺」→「确认铺位」→ 确认页显示「K817 / 07 车 3 号中铺 / ¥428」。
4. 点「提交订单」→ 行程凭证出现：红头 K817、检票口 12B、条形码与三孔票根。

异常恢复：
1. 回首页再查询，点带 ◆ 的 K117 → 任选一枚可选铺位 → 提交订单。
2. 确认售罄视图：斜盖红戳「已售罄」，文案指出「K117 次硬卧」，并显示路线条件保留条。
3. 点「返回班次列表改选」→ 确认路线条仍是「北京西 → 成都 · 11月12日 周四」。
4. 改选 T7 → 点带 ◆ 的「12 号下铺」→ 提交 → 再次售罄且指出「07 车 12 号下铺」。
5. 点「仅换铺位」→ 改选「5 号上铺」→ 提交 → 成功生成 T7 行程凭证。
