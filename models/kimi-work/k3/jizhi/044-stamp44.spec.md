## 内容与数据

- 品牌：顶部 34px 圆形「邮」戳 +「方寸集」+ 副标「STAMP-44 · 集邮同好社区」；动态流标题「同好动态」+ 胶囊「今日新邮 3 枚」。
- 初始动态 3 条，顺序固定：「庚申年金猴整版，终于圆梦」（北平邮痴 · 今天 09:20 · 公开 · 赞 46 · 评论 12）、「蓝军邮实寄封，品相九品」（岭南小邮差 · 昨天 21:05 · 仅同好 · 赞 18 · 评论 6）、「黄山云海纪念张首日封」（江南集邮客 · 周三 15:40 · 公开 · 赞 27 · 评论 9）。
- 编辑页字段顺序：邮品描述（textarea，占位「写下这枚邮票的来历、品相与故事…」）→ 可见范围（公开 / 仅同好 / 仅自己，默认公开）→「模拟网络故障」开关（说明「开启后，下一次发布将失败」）→ 失败横幅（默认隐藏）。

- 新发动态作者为「我」，时间格式「今天 HH:MM」，标题取正文首行超 14 字截断加「…」，赞与评论初始 0。

## 产品边界

一个集邮爱好者社区的发帖原型：动态浏览（邮票卡片流）、撰写新动态、三档可见范围、发布入流与失败重发。不含：评论与点赞的真实交互、图片上传（邮票图由内联 SVG 示意）、关注关系、私信、账号体系、真实网络层（故障为开关模拟）。

## 正常流程

1. 打开页面，动态流展示 3 条邮票卡，底部红色入口「＋ 晒一枚新邮」。
2. 点击入口进入编辑页，输入「今日收到一轮生肖兔大版，齿孔锋利，原胶完整。」
3. 可见范围保持默认「公开」（或改选「仅同好」）。
4. 点击「盖戳发布」：视图切回动态流，新卡置顶，作者「我」、时间「今天 HH:MM」、带「已盖戳」戳记，toast 提示发布成功。

## 异常触发与恢复

1. 触发：在编辑页打开「模拟网络故障」开关（说明文字「开启后，下一次发布将失败」），toast 确认已开启。
2. 输入正文、选择「仅同好」可见范围，点击「盖戳发布」：页面不跳转，红色横幅显示「发布未完成：检测到网络故障，本条动态未能寄出。草稿与可见范围已完整保留…」，按钮变红并改为「重新盖戳发布」；正文与「仅同好」选中态原样保留。
3. 恢复：关闭「模拟网络故障」开关，点击「重新盖戳发布」。
4. 结果：视图切回动态流，新卡置顶且徽标显示「仅同好」，横幅与失败样式清除，toast 提示「已盖戳，动态发布成功」。

## 数据变化

- `POSTS` 数组按倒序渲染动态流；发布成功时向数组头部 `unshift` 一条 `{title, txt, who:"我", time:"今天 HH:MM", vis: 当前选中可见范围, likes:0, comments:0, mine:true}`。
- 发布失败不写 `POSTS`：仅置失败 UI 态（横幅显示、按钮文案与变色、`failedOnce` 标记），textarea 值与 radio 选中项不做任何重置。
- 发布成功后清空 textarea、可见范围复位为「公开」、按钮恢复「盖戳发布」蓝底并禁用（等待新输入）。
- 可见范围读取自 `name="vis"` 的选中 radio，取值「公开 / 仅同好 / 仅自己」，直接写入新卡的徽标与数据字段。

## 人工验收步骤

正常闭环：

1. 打开页面 → 确认动态流 3 条卡、底部红色「＋ 晒一枚新邮」。
2. 点进入口 → 输入正文 → 发布按钮由灰蓝禁用变为可用蓝。
3. 可见范围选「公开」→ 点「盖戳发布」。
4. 预期：回到动态流，顶部出现新卡（作者「我」、右上角「已盖戳」红戳、赞 0 评论 0），toast 提示成功。

异常恢复：

1. 再点入口 → 打开「模拟网络故障」→ 输入「整版猴票细节图已补拍。」→ 可见范围改选「仅同好」。
2. 点「盖戳发布」→ 预期：停在编辑页，红横幅提示发布未完成，正文与「仅同好」保留，按钮变红「重新盖戳发布」。
3. 直接再点一次（开关仍开）→ 预期仍失败、内容仍在。
4. 关闭「模拟网络故障」→ 点「重新盖戳发布」→ 预期：回到动态流，新卡置顶且徽标为「仅同好」，横幅消失，toast 提示发布成功。
