# 单题质量

题库只定这一题的**职责**和 `must_have`。气质、色、品牌、时代感由你按自己的品味发明。缺一块必做模块，这题就不算完成。

## 页面

- 一个 html 文件就能打开，不依赖 npm、打包、外网字体、外网图片。
- 看起来像已上线的产品，不像线框或组件展示。
- 文案用中文，写得像真产品，不用 lorem，不用「页面标题」「按钮按钮」。
- 主按钮、输入框、卡片、悬停/焦点/禁用能看出来。
- 至少有一处真正能点的交互（切换、展开、步进、加减、选中），不是纯静图。
- 桌面题在约 1280 宽站得住，缩到 768 不碎。
- 移动题（`viewport` 为 `mobile`）按约 390 宽设计；在宽屏上把界面放进一只手机框里，方便展厅卡片看出是手机页。
- 尊重 `prefers-reduced-motion`：减少连续动画，保留必要反馈。

## 40 套必须是 40 种方案

每一题自带一套完整品味：色、字、材料感、疏密、时代气质。任意两题至少错开两项：信息密度、色彩冷暖、材料/时代气质、构图制度。不要出现「换个标题的同一套皮肤」。

只根据题库和自己的品味写。其他模型的页面、规范、展厅一律不打开。若交卷后和别人像，视为品味一致。

## 规范

`.spec.md` 是可执行的复现合同，按 `catalog/spec-template.md` 写满：布局边界、色彩、字号、间距、圆角、组件状态、响应式、动效和验收项都必须使用 HTML 中的真实值或可观察规则。不要用“高级感”“留白充足”或一段提示词代替尺寸与状态。

`.intent.md` 按 `catalog/intent-template.md` 填写，只解释设计意图、适用场景、非目标和辅助复刻提示词。它帮助人理解取舍，但不参与结构、尺寸、状态或交互验收。

复现者应当只依赖 HTML 之外的 `.spec.md` 就能重建相同布局制度、设计令牌和核心行为；`.intent.md` 只用于理解方向。规范中的十六进制色值必须实际出现在对应 HTML 中。
